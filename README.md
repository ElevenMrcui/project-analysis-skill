# 全流程项目分析 Skill

先查看 [中文交互示例](docs/project-analysis.html)，Skill 入口在 [project-analysis/SKILL.md](project-analysis/SKILL.md)。整个 `project-analysis` 目录是可迁移的 Skill 包，本次只保存到桌面工作区，没有全局安装。

## 用途

对多语言、前后端联合项目开展可追溯的全流程分析，报告输出到目标工作区的 `docs` 目录。最高优先级是**事实正确、分析深入、覆盖完整、中文易懂**，然后才是视觉表现。

| 能力 | 交付内容 |
| --- | --- |
| 全链路分析 | 入口、决定行为的实现、业务规则、权限、异常、事务、消息、数据及发布运维 |
| 防止静默遗漏 | 独立文件清单、发现台账、逐 ID 对账、双向引用、缺口记录 |
| 多语言适配 | 前端、服务端、SQL、任务、基础设施、移动端、CLI、SDK 等按实际技术栈调查 |
| 中文讲解 | 用途、运作步骤、说明性示例、失败后果、范围限制、术语解释 |
| 必备图示 | 项目架构图、功能流程图、细节功能流程图；按场景补充时序、数据流、ER、生命周期图 |
| 数据字典 | 全部表与字段、类型、键/约束/索引、默认值、可空、注释、敏感级别、表关系及字段流向 |
| 交互报告 | 检索、筛选、分页、图形缩放、证据详情、深浅主题、完整 JSON/CSV 导出和打印 |

示例是虚构订单系统，含 19 个对象、2 张表、7 个字段、7 张图、2 条链路。它不是当前工作区的真实业务分析，也不代表真实产品测试通过。

## 前提

- 使用能读取源码、调用工具并执行 Skill 的编程 Agent。
- 本地有 Python 3.9+；基线工具仅使用标准库，不要求 Node.js。
- 提供全部授权的前后端/数据仓库路径。缺失仓库或未接入数据库会被记录为限制。
- 优先使用 codebase-memory MCP；不可用或索引不覆盖时，使用语言原生工具、LSP 和源码检查，并披露差异。
- HTML 已内嵌 Lucide 与 Mermaid，可直接离线打开，无需启动开发服务器。

## 使用步骤

### 直接调用

在目标项目的 Copilot 对话中给出以下要求，并将路径换成实际位置：

```text
读取并执行 <你的 skill 路径>/project-analysis/SKILL.md。
分析当前工作区全部项目；如有关联前后端仓库，将其共同纳入范围。
优先保证分析深度、事实正确和功能/数据覆盖，不只总结目录或 README。
报告使用中文，先讲清业务，再给实现细节与源码证据。
包含架构图、每个功能的流程与细节图；涉及数据库时包含完整字段字典、ER 关系及数据流向。
输出到当前工作区 docs 目录；不得修改业务源码或执行生产写操作。
未知信息和未执行检查须明确保留，不宣称绝对零遗漏。
```

### 作为项目 Skill 安装

将**整个** `project-analysis` 目录复制到目标项目的 `.github/skills/` 下，入口应为 `.github/skills/project-analysis/SKILL.md`。不要只复制入口文件，否则脚本、规则和图形资源会缺失。已有同名目录时先保留旧版本，不能直接覆盖。

重新加载技能后可使用 `/project-analysis`，或在对话中明确要求执行该 Skill。具体自动发现范围取决于所用 Agent 和编辑器配置。

### 本地验证此包

在当前桌面工作区终端执行：

```sh
python3 -m unittest discover -s project-analysis/scripts -p 'test_*.py' -v
```

重新生成**虚构示例**会覆盖当前示例产物，只用于本包演示，不可替代真实分析：

```sh
python3 project-analysis/scripts/make_example.py --workspace .
open docs/project-analysis.html
```

真实项目应由 Agent 依次执行 inventory、init、调查与记录、validate、render；具体命令和字段契约见 Skill。脚本负责清单、校验与展示，**不自动理解所有语言的业务语义**。

## 通过标准

分别判断三项：分析深度、范围覆盖、讲解易懂。结构校验通过不等于语义正确，也不等于读者理解验证通过。功能/API/表/任务缺少必需讲解、图示缺失、连接字段错误、候选 ID 不一致或存在开放缺口时，不能把报告标为完整。

`validate` 返回 0 表示其检查的声明范围内对账通过，返回 1 表示未完成；`render` 返回 0 仅表示 HTML 已写出，不表示分析通过。

## 排错

- 看不到图：确认复制了整个包，并从生成后的 HTML 打开，而不是直接打开模板。
- 没有运行库权限：报告只能说明仓库定义的结构，运行库差异继续保留为缺口。
- MCP 或特定解析器不可用：按 Skill 退回局部源码核验，不伪称已运行相关工具。
- 显示覆盖未完成：查看“覆盖与缺口”，解决具体未核实项，不删除记录来获得通过状态。
- 示例显示未计量：示例没有真实源码文件，分母为零，不能显示 100%。

## 证据清单

真实分析需保留仓库快照、独立清单、发现原始结果、分析数据、校验回执、图示模型、脱敏证据、浏览器截图和验证记录，全部位于目标 `docs/project-analysis/` 下。

本包工具和 UI 的实际验收见 [验证记录](docs/project-analysis/evidence/validation.md)。设计参考及 GitHub Star 快照见 [参考项目](project-analysis/references/ui-research.md)。

## 提交模板

```text
报告：docs/project-analysis.html
范围：仓库、快照、环境与明确排除项
分析深度：决定点、规则、分支、数据和副作用的核验结果
覆盖：已审阅/应审阅文件，已映射/已发现候选，表/字段/图示数量
易懂性：中文用途、步骤、示例、失败和术语解释的检查结果
验证：实际执行的工具测试、浏览器检查及结果
限制：未知项、未接入系统、未执行检查、未做真实读者测试
结论：范围内已对账或覆盖未完成；不作绝对零遗漏保证
```
